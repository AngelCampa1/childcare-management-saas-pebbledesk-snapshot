# PebbleDesk Design Context

### Button Geometry

Buttons are pills. Use fully rounded button geometry (`border-radius: 9999px`, `rounded-full`, or equivalent) for every button and button-styled CTA, including icon buttons, segmented/toggle controls, and link-buttons. Cards, inputs, dialogs, tags, and content containers may keep their own radii; button-like controls should not use square, `rounded-md`, or `rounded-lg` corners unless the user explicitly asks for that exception.

## Users

**Primary:** Licensed childcare center directors and owner/operators who manage subsidy reimbursements, staff-to-child ratio compliance, and state licensing audits.

**Key traits:** Non-technical (early childhood educators by training, not software people). Time-starved (managing children, staff, parents, and regulators simultaneously). Budget-conscious (1-3% margins). Risk-averse (switching software affects billing, compliance, and parent relationships). They use the app during the workday in bright indoor environments, often on tablets.

**Job to be done:** Keep records audit-ready without manual spreadsheet reconciliation. Know that ratios are in compliance right now. Get subsidy claims submitted correctly the first time.

## Brand Personality

**Three words:** Warm, Sturdy, Practical

**Voice:** Speak like a trusted colleague who happens to know compliance inside and out. Not a faceless corporation, not a slick startup. Use childcare admin language (ratio tracking, subsidy reconciliation, state audit, licensing compliance). Avoid generic SaaS jargon (workflows, pipelines, seamless).

**Emotional goal:** Relief. "This used to take me hours. Now it just works."

## Aesthetic Direction

**Visual tone:** Gusto-inspired — approachable, friendly, professional. Designed for non-technical SMB owners who distrust software that tries too hard to look impressive.

**Reference:** Gusto (payroll/HR for SMBs). Warm, organized, builds trust through clarity rather than data density. Friendly illustrations and clear typography help non-technical users feel at home.

**Anti-reference:** Complex enterprise software (Salesforce, etc.). Directors don't have time to learn a cockpit. Every screen should be immediately understandable — no training required.

**Theme:** Light mode only. The target audience works in bright daytime environments (childcare centers). Dark mode adds complexity without serving the user.

## Design Principles

### 1. Clarity Over Cleverness
Every screen should be immediately understandable. No progressive disclosure that hides critical compliance data. No clever interactions that require learning. If a director can't figure out what to do in 3 seconds, the design has failed.

### 2. Compliance-First Hierarchy
The most important information on any screen is: are ratios OK, are records audit-ready, are claims on track. Visual hierarchy should always surface compliance status before operational details. Green/amber/red status indicators are the first thing the eye hits.

### 3. Warm Professional
The interface should feel like a well-organized office, not a Silicon Valley dashboard. Rounded corners (0.5rem), generous whitespace, clear section labels. No gradients, no glassmorphism, no visual tricks. Trustworthy and approachable.

### 4. Reduce, Don't Add
Every element on screen must earn its place. If removing something doesn't reduce understanding, remove it. Directors are already overwhelmed — the interface should calm, not stimulate. Prefer fewer, larger elements over dense data grids.

### 5. One Action Per Screen
Each page should have one clear primary action. The attendance page checks children in. The ratio page shows compliance status. The subsidy page tracks claims. Don't combine workflows into multi-purpose screens.

## Component Guidelines

- **Shadcn/UI:** New York style. Use built-in components before creating custom ones.
- **Border radius:** 0.5rem (8px) default. Consistent across cards, buttons, inputs.
- **Spacing scale:** Tailwind defaults. Prefer `p-4`/`p-6` for card padding, `gap-4`/`gap-6` for layouts.
- **Icons:** Lucide React. 16px (size-4) inline, 20px (size-5) for nav items.
- **Tables:** Use Shadcn DataTable for list views. Keep columns minimal — 4-6 max.
- **Forms:** Single-column layouts. Clear labels above inputs. Validation messages below.
- **Status indicators:** Pill badges with semantic colors (green=compliant, amber=warning, red=violation).
- **Loading states:** Skeleton loaders, not spinners. Keep layout stable.
- **Empty states:** Helpful illustration + description + CTA. Never just "No data."
- **Micro-interactions:** Always add hover effects, focus rings, smooth transitions on state changes, and subtle feedback on interactive elements. The UI should feel alive and responsive.

## Loading Patterns

Use Shadcn `Skeleton` components for all loading states. Never spinners. Skeletons should match the layout of the content they replace so the page doesn't shift on load. Use optimistic updates for mutations — don't show skeletons for actions the user just took.
