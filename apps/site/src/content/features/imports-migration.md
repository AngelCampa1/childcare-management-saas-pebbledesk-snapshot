## The problem: Switching software feels risky when live data has nowhere clean to go

Centers are right to ask how setup works before they care about feature depth. A strong feature page is not enough if the first month still looks like manual re-entry.

## The PebbleDesk solution: Start from CSV imports and practical migration presets

PebbleDesk supports CSV import and includes Brightwheel and Procare presets so the first data load starts from something realistic. That gives single-site centers a practical self-serve path and gives larger operators a better foundation for rollout planning.

## What to review next

Go to Enrollment & Records if your main concern is roster and family structure. Go to Multi-Location Oversight if you are evaluating rollout across more than one center.

## What a safer migration should include

A practical migration plan starts with a small sample export, field mapping, duplicate review, and a decision about what needs to be cleaned before the full import. That prevents a center from moving bad roster, guardian, billing, or enrollment data into a new system and then treating cleanup as a staff training problem.

PebbleDesk's import story is intentionally operational. {{claim.migrationSupport}} The preview step matters because directors need confidence that duplicates and mismatched fields will be visible before records become part of daily operations.

## Accuracy note

PebbleDesk supports import workflows and named migration presets, but it does not claim every customer receives a white-glove migration. Directors should expect a practical first-load path with preview and cleanup steps, plus rollout help when the plan and setup call for it.

## What directors should review next

A migration page should lower anxiety without pretending setup is magic. Directors still need to review the export, clean obvious issues, and decide what belongs in the new system. PebbleDesk gives that work a more practical starting point with CSV import and named presets for common moves from Brightwheel or Procare. The reason this connects to [enrollment records](/features/enrollment-records), [billing and payments](/features/billing-payments), and multi-location rollout is simple: bad imported data becomes daily friction. A careful first load saves time later. PebbleDesk does not claim that every historical note, attachment, or agency-specific field will move perfectly. It gives directors a preview-oriented path so they can catch duplicates and mapping issues before the records become part of the official operating workflow.
